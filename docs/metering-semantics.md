# 计量语义说明

本文档描述 Traffic Monitor 的计量口径与各类网络异常下的行为，是 `TrafficMonitor` / `TrafficMath` 实现的权威说明。

## 计时口径（开始时间与已运行）

- 每个模块（Wi-Fi / iPhone Share）拥有**独立的开始时间与累计**。
- 开始时间 = 应用启动，或该模块最后一次「重置计量」的时刻（**墙钟时间**）。
- 「已运行」= 开始时间到当前的墙钟流逝，**不扣除系统休眠**——与运营商按自然时间计费的口径一致。
- 计时窗口与流量累计互相独立：休眠期间「已运行」照走，累计自然冻结（没有流量就没有计数）。

## 采样与累计

- 每秒一次 `sysctl(NET_RT_IFLIST2)` 采样，接口字节计数为内核 64 位累计值（开机以来）。
- 每拍只统计**上一拍也存在**的接口的字节差；负差值（计数器回绕/重置）钳位为 0。
- 因此：
  - **接口断开**（拔线 / 离开热点 / iPhone 断开 USB）：该模块累计自然冻结，恢复后自动续计。
  - **拔插导致接口销毁重建**（计数器从 0 重新开始）：≥1 秒的插拔间隙会让基线自然重建，重建当拍计 0，此后正常续计——不会把旧计数误当新流量，也不会丢复建后的流量。
  - **采样失败**（系统调用偶发出错）：该拍整体跳过，基线保留，下一拍照常计差。
- 系统休眠唤醒：休眠期真实流量在唤醒后第一拍**计入累计**（该发生的都算）；但速率按重新基线处理（该拍速率记 0），避免出现跨越休眠期的假尖峰。采样间隔超过 5 秒即触发此逻辑。

## 速率展示

- 速率 = 相邻两拍的字节差（每秒一拍），因此数值天然是「最近 1 秒的平均值」。
- 历史曲线每秒入一个样本；空闲秒也入 0，保证时间线连续。

## 为什么不展示延时 / 抖动

本应用是**纯被动**计量：只读内核计数器，自身不产生任何网络流量。字节计数里不含时延信息；测量延时/抖动必须主动探测（如持续 ping 网关），这会：

1. 污染被计量的流量（探测包本身被计入）；
2. 带来持续的 CPU/耗电开销与实现复杂度；
3. 只能反映到网关的路径质量，与"用了多少流量"这一核心问题无关。

故明确不做。若未来需要网络质量面板，应作为独立的主动探测模块实现，与计量彻底分离。
