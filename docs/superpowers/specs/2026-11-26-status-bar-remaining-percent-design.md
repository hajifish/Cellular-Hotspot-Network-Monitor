# 状态栏新增「剩余」展示项 + 开关文案缩短 — 设计文档

日期：2026-11-26　分支：`feature/status-bar-remaining-percent`

## 意图与背景

状态栏目前可选展示两组信息（累计流量 / 实时速率），各自一个开关。用户希望再加第三种可选展示：**告警剩余百分比**——设置告警阈值后，状态栏直接显示还剩百分之几（例：告警 20 GB，已用 15 GB → 显示 25%）。同时把三个开关的文案缩短（累计流量→累计、实时速率→实时、新增→剩余），否则主页右上角放不下三枚开关。

## 目标

- 主页右上角新增第三枚开关「剩余」，控制状态栏是否展示告警剩余百分比。
- 状态栏第三列渲染剩余百分比，与现有「↑/↓ 两行竖排」列并排。
- 三枚开关文案缩短为「累计 / 实时 / 剩余」，胶囊收窄后三枚并排放得下。
- SelfTest 覆盖新逻辑（百分比计算、列渲染、开关默认值）。

## 非目标 / 反目标

- 不改主页汇总条告警文案（「剩 X · 已用 Y%」保持现状）。
- 不动告警设置、触发、里程碑逻辑。
- 状态栏剩余列不显示具体剩余字节数（只显示百分比）。

## 约束

- 窗口 720pt 宽，右上角三枚胶囊需与左侧汇总条（右边缘 x=480）不重叠。
- 状态栏文字最终渲成位图，字号 8pt、单色白为基线（菜单栏恒深色底）。
- 无 XCTest：测试走内置 SelfTest 主程序（仓库惯例）。

## 方案取舍

1. **（采纳）独立布尔开关 `statusBarShowRemaining`**：与现有两个开关同一模式（UserDefaults Bool，默认关），Formatter 增加第三列。实现最小、与既有迁移/存储逻辑一致。
2. 三态单选模式（icon/totals/rates/remaining 各一）：推翻现有独立开关模型，需数据迁移，改动大，弃。
3. 复用主页汇总条文案进状态栏（含剩余字节数）：状态栏横向空间放不下「剩 X · 已用 Y%」，且用户明确只要百分比，弃。

## 细节决策

- **百分比计算**：`剩余% = (阈值 − 进度) ÷ 阈值 × 100`，四舍五入取整；进度 ≥ 阈值或已触发 → 0%。
- **告警未设置时**：该列整体不渲染（开关开着也不占位），不显示无意义的占位符。
- **颜色**：剩余 >20% 白色；≤20% 橙色（.systemOrange）；0%/已触发红色（.systemRed）。与主页汇总条 armed/fired 的橙红语义一致，状态栏瞄一眼可辨紧迫度。
- **布局**：剩余列排在实时列之后（最右）；单值跨「↑/↓」两行垂直居中。
- **开关布局**：三枚胶囊各 62pt 宽（球 18 + 两字标签 11pt），从右缘 708 起排：剩余 646、实时 588、累计 530→即累计 530 位置不动，改为 530/596/662？——按 62pt+4pt 间距排布，具体坐标执行时以不重叠、右缘对齐 708 为准。
- **默认值**：`showRemaining` 默认关（与 showTotals 一致，不惊扰未用告警的老用户）。
- **已触发但阈值未设**（理论不存在）：按未设置处理，不渲染。
